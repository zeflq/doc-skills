# Test dr-08 — _index.md regeneration

## Behavior

> After every workflow (CREATE, UPDATE, SYNC) that writes at least one file, `_index.md` is regenerated as a plain TOC. SYNC where all topics are SKIP must not touch `_index.md`. `_index.md` itself is never classified as a sync topic.
> **When:** Any successful write to `{root}`.

## Why this test exists

`_index.md` is the single discovery point for all agent notes. It must stay in sync with the notes directory after every write, and must never be stale or incorrectly listed as a sync topic.

## Setup

`.pi/notes/` exists with one doc: `back.auth.md`. No `.last-sync`.

Config:
```xml
<config>
  root: .pi/notes/
  skip_patterns: ["**/*.lock"]
</config>
```

---

## Run 1 — CREATE workflow

**Prompt:**
```
create a note for the proxy module
```

### What to observe

After doc-writing CREATE writes `front.proxy.md` (or similar), `_index.md` is regenerated with both `back.auth.md` and the new file listed.

### Checks — Run 1

| # | Check | Pass condition |
|---|-------|----------------|
| C1 | `_index.md` written after CREATE | `{root}/_index.md` exists and was updated |
| C2 | Both docs listed | `_index.md` contains links to `back.auth.md` and the new file |
| C3 | Plain list — no metadata | no dates, no descriptions, no frontmatter in the list items |
| C4 | `_index.md` excludes itself | `_index.md` not listed as a link in `_index.md` |
| C5 | `.last-sync` not listed | `.last-sync` not present in `_index.md` |

## Run 2 — UPDATE workflow

**Prompt:**
```
update the auth doc — add a logout section
```

### What to observe

After doc-writing UPDATE writes the change, `_index.md` is regenerated. The list is the same as before (no new files added, but index still regenerated).

### Checks — Run 2

| # | Check | Pass condition |
|---|-------|----------------|
| C6 | `_index.md` regenerated after UPDATE | file is rewritten — not skipped |
| C7 | List unchanged in content | same links as before — no file added or removed |

## Run 4 — SYNC with all SKIP

**Prompt:**
```
sync from last 1 commit
```

*(one commit touches only `package-lock.json` → SKIP)*

### What to observe

Step 7 must not execute — all topics were SKIP, no files were written.

### Checks — Run 4

| # | Check | Pass condition |
|---|-------|----------------|
| C10 | `_index.md` not rewritten | file timestamp unchanged — step 7 skipped |

**Prompt:**

```
sync from last 3 commits
```

User replies: `yes`

| # | Check | Pass condition |
|---|-------|----------------|
| C12 | `_index.md` not classified | step 4 skips `_index.md` — no CREATE or UPDATE for it |

---

## Fail signals

- CREATE or UPDATE completes without writing `_index.md`
- SYNC step 7 runs even when all topics were SKIP
- `_index.md` links to itself
- `_index.md` includes dates or descriptions in list items
- `_index.md` classified as a CREATE or UPDATE topic during SYNC
- Step 7 runs before step 5 completes
